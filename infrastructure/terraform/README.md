# Terraform (AWS data plane)

Optional. The platform runs fully with `make dev`; this directory sketches
where its state would live on AWS. It is **validated, not applied**:
`terraform fmt -check` and `terraform validate` pass (CI runs both), but no
`plan` or `apply` was run, because that needs AWS credentials and creates
billable resources. Treat it as a reviewed starting point, not a tested
deployment.

## What it creates

| File | Resources |
| --- | --- |
| `network.tf` | VPC, private subnets across 2-3 zones, security groups so that PostgreSQL, Redis and Kafka accept traffic only from the `app` group |
| `kafka.tf` | Provisioned MSK, 3 brokers, TLS in transit, SASL/SCRAM, KMS-encrypted credentials in Secrets Manager, Prometheus JMX/node exporters |
| `postgres.tf` | RDS PostgreSQL 16, encrypted, SSL enforced, backups, deletion protection, master password managed by RDS in Secrets Manager |
| `redis.tf` | ElastiCache Redis 7 with failover, at-rest and in-transit encryption, AUTH token in Secrets Manager |
| `ecr.tf` | One immutable, scan-on-push ECR repository per service image |

## What it does not create

Compute. There is no ECS service, EKS cluster, load balancer, DNS, NAT or
TLS certificate: the services need an environment-specific home, and the
Compose file already describes their wiring. Attach the workloads to the
`app_security_group_id` and private subnets from the outputs, push images to
the ECR URLs, and set:

```text
KAFKA_BOOTSTRAP_SERVERS=<kafka_bootstrap_brokers_sasl_scram>
KAFKA_SECURITY_PROTOCOL=SASL_SSL  KAFKA_SASL_MECHANISM=SCRAM-SHA-512
KAFKA_SASL_USERNAME / KAFKA_SASL_PASSWORD   (from kafka_credentials_secret_arn)
KAFKA_TOPIC_REPLICATION_FACTOR=3  KAFKA_TOPIC_MIN_INSYNC_REPLICAS=2
POSTGRES_HOST=<postgres_endpoint host>  POSTGRES_SSLMODE=require
REDIS_HOST=<redis_primary_endpoint>  REDIS_SSL=true  REDIS_PASSWORD   (from redis_auth_secret_arn)
```

Also not handled: the extra `mlflow` database and role (see
`infrastructure/postgres/init`), remote state (add a `backend` block for your
bucket), Alertmanager, and authentication for the API. The Redis AUTH token
and Kafka password are generated by Terraform, so they are in its state file:
keep state in an encrypted, access-controlled backend.

## Use

```bash
cd infrastructure/terraform
cp terraform.tfvars.example terraform.tfvars
terraform init
terraform plan      # review: MSK and RDS cost money from the moment they exist
```

## Decisions worth knowing

* **MSK provisioned, not Serverless.** Serverless supports only IAM
  authentication, while the services speak SASL PLAIN/SCRAM.
* **Three brokers and replication factor 3** match the topology in
  `shared/kafka/topics.py` and the `min.insync.replicas=2` durability setting
  that `acks=all` producers rely on.
* **Secrets never appear in the repository.** `terraform.tfvars` and state are
  git-ignored; `.terraform.lock.hcl` is committed to pin provider versions.

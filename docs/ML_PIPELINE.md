# ML Pipeline: Features, Labels, Splits and Baselines

This document covers Phase 6: the problem definition, the shared feature
library, how labels and splits are built without leakage, and what the
baselines show. Model results are generated by `make baselines` into
[BASELINES.md](BASELINES.md); every number below comes from that report.

## Problem definition

| | |
| --- | --- |
| Primary task | Direction of the forward log return over **5 sessions** (`y_up = 1` if `log(close[t+5] / close[t]) > 0`) |
| Secondary task | The forward 5-session log return itself (regression) |
| Unit | One row per (symbol, session), 12 US large caps, daily bars 2010-2026 |
| Decision time | After the close of session *t*; features use bars up to and including *t* |

A weekly horizon was chosen over next-day because daily direction is close to
a coin flip with very low signal-to-noise, and weekly is still short enough to
be served from the live stream. An optional neutral band (`|r| < epsilon` is
labelled neutral and dropped from the binary task) is supported by
`LabelConfig.neutral_band`; it defaults to 0 so no rows are silently removed.

## Features (`shared.features`, version `fs-1.0.0`)

One implementation, `FeatureComputer`, is used both offline (replayed over
history to build the training set) and online (fed bar by bar in the stream).
There is no separate pandas version for training, so training/serving skew
cannot come from two diverging implementations.

* **Incremental and causal.** State is a set of bounded windows and EMAs; each
  `update(bar)` sees only that bar and earlier ones.
* **Scale-free.** All 28 features are returns, ratios, normalised distances or
  bounded oscillators, so they mean the same for a $20 and a $2,000 stock.

| Group | Features |
| --- | --- |
| Returns | `ret_1`, `ret_5`, `ret_10`, `ret_20`, `ret_lag_1..4` |
| Bar shape | `gap`, `hl_range`, `close_pos` |
| Trend | `close_sma10/20/50`, `sma10_sma50`, `macd_norm`, `macd_hist_norm` |
| Volatility | `vol_10`, `vol_20`, `vol_ratio_10_60`, `atr_14_norm`, `bb_width_20`, `bb_pos_20` |
| Momentum | `rsi_14` (0-1 scale) |
| Volume | `volume_ratio_20`, `volume_change` (log1p ratios, finite on zero volume) |
| Calendar | `day_of_week`, `month` |

* **Warm-up.** A row is usable only after 61 bars, when every feature exists
  (`vol_ratio_10_60` needs 60 returns). Incomplete rows are dropped, never
  filled.
* **Gaps.** Cleaning records missing sessions instead of imputing prices
  ([DATA_QUALITY.md](DATA_QUALITY.md)). A bar after a gap resets the computer,
  because a "1-bar return" across a gap is not a 1-bar return.
* **Versioning.** `FEATURE_SET_VERSION` is written into the dataset path and
  metadata; a model trained on one feature set will refuse another (Phase 8).

## Labels (`stockml.features.dataset`)

For each row: `y_return` = forward 5-session log return, `y_up`, `y_class`
(with the neutral band) and `label_end` = date of the last bar the label
uses. A label is NaN if a gap falls inside *t+1..t+5* or the series ends,
and those rows are dropped. `label_end` is what makes purging possible.

## Splits and leakage controls (`stockml.training.splits`)

| Split | Sessions | Rows | Use |
| --- | --- | ---: | --- |
| train | 2010-03-31 .. 2019-12-23 | 28,691 | fitting |
| validation | 2020-01-09 .. 2022-12-22 | 8,952 | model selection, thresholds |
| test | 2023-01-10 .. 2026-09-18 | 11,112 | **held out**; touched once, for the final report (Phase 7) |

Controls, each covered by a test:

1. **Chronological only.** No random shuffling, and the **same date boundary
   for all symbols**, so one stock's future cannot train a model evaluated on
   another's past.
2. **Purging.** Training rows whose label window ends after the boundary
   (`label_end > boundary`) are removed; otherwise the last week of training
   would contain validation prices.
3. **Embargo.** The first 5 sessions after each boundary are dropped from the
   evaluation side, because their features overlap the training labels.
4. **Point-in-time features.** Tests assert that (a) the incremental features
   equal an independent pandas batch reference for all 28 features, (b)
   features at *t* are identical whether the series is truncated at *t* or
   continues, and (c) a price shock injected at *t+1* changes nothing at *t*.
5. **Fit-on-train scaling.** The scaler lives inside the model pipeline and is
   fitted on each training fold only.
6. **Honest uncertainty.** Overlapping 5-session labels are serially
   correlated, so accuracy intervals use an effective sample size of
   `n / horizon`; a naive interval would be about 2.2x too narrow.

**Walk-forward validation** uses expanding windows: train on everything before
year *Y*, test on year *Y*, for *Y* = 2015..2022, with the same purge and
embargo. It stays inside the development period, so the test set is untouched.

## Baselines

| Task | Model | What it represents |
| --- | --- | --- |
| Direction | `majority` | Always predict the training majority class ("up") |
| Direction | `momentum` | Predict up if the last 5-session return was positive |
| Direction | `logistic` | Standardised logistic regression on all 28 features, L2 (`C=0.1`) |
| Return | `zero` | Predict a 0 return (random walk) |
| Return | `train_mean` | Predict the training mean return |
| Return | `ridge` | Ridge regression on all features (`alpha=10`) |

### Results

Direction, validation (2020-2022): the base rate (share of "up" weeks) is
0.529.

| Model | Accuracy (95% CI) | ROC-AUC |
| --- | --- | ---: |
| majority | 0.529 (0.505-0.552) | n/a |
| momentum | 0.511 (0.488-0.534) | 0.503 |
| logistic | 0.524 (0.501-0.548) | 0.495 |

Walk-forward, 8 yearly folds (2015-2022):

| Model | Accuracy mean ± sd | Accuracy - base rate | ROC-AUC |
| --- | --- | ---: | ---: |
| majority | 0.554 ± 0.042 | -0.009 | n/a |
| momentum | 0.500 ± 0.019 | -0.063 | 0.483 |
| logistic | 0.549 ± 0.039 | -0.014 | 0.506 |

Logistic per fold (accuracy / base rate / AUC): 2015 .539/.543/.517,
2016 .562/.572/.504, 2017 .592/.602/.523, 2018 .528/.523/.521,
2019 .595/.605/.508, 2020 .545/.560/.474, 2021 .564/.562/.487,
2022 .463/.536/.516.

Return regression: validation R² is -0.0012 (zero), -0.0006 (train mean) and
-0.0138 (ridge); walk-forward ridge R² is -0.0150 ± 0.0225.

### Interpretation

* **No baseline beats the base rate.** Logistic regression's accuracy is
  within noise of always predicting "up", its AUC is about 0.5, and it beats
  the base rate in only 2 of 8 folds, by at most 0.005. Ridge does worse than
  predicting zero. The 55% "accuracy" is the market's upward drift, not skill.
* **Momentum loses** at this horizon (AUC 0.483 walk-forward), consistent with
  short-term reversal in large caps rather than continuation.
* **The pipeline can learn when there is something to learn.** A unit test
  plants a known signal in synthetic data; the same code reaches AUC > 0.85
  and R² > 0.3. So the null result is about the data, not a bug.
* **The largest logistic coefficients** (`atr_14_norm`, `close_sma20`,
  `macd_norm`, `vol_10`) mostly describe volatility regime and short-term
  stretch. They are reported for transparency; with AUC ≈ 0.5 they should not
  be read as a trading rule.
* **Accuracy is not profitability.** Even a model with a real edge can lose
  money after transaction costs and turnover. Phase 7 adds a cost-aware
  backtest before any claim of usefulness.

This is the expected outcome for public daily OHLCV of heavily traded stocks.
Phase 7 tests whether non-linear models (gradient boosting) find anything the
linear baseline cannot; the comparison will be reported against these numbers
whatever it shows.

## Reproducing

```bash
make data && make data-quality   # pinned snapshot -> data/processed/.../cleaned.parquet
make baselines                   # dataset + docs/BASELINES.md + data/reports/baselines.json
```

The dataset is written to
`data/features/<dataset>/<revision>/fs-1.0.0/dataset.parquet`. All models are
deterministic (fixed seed where a solver takes one), so reruns produce identical
numbers.
